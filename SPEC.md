# Product & Technical Specification: notes-manager

Local-first desktop notes + task tracker for Technical Delivery Management. Meeting notes and action items live in one workspace. **Revision 2 (2026-11-13)** supersedes the original spec: the Google Apps Script / `/Bridge` dead-drop and `.ics` approaches are removed; Google Workspace integration uses an isolated Electron session instead.

Status legend: ✅ done · 🔜 next · ⬜ planned

---

## 1. Principles & Constraints

- **Local-first, human-readable.** Notes are Markdown with YAML frontmatter in a vault folder. SQLite is a *disposable derived index*: deleting it loses nothing.
- **No corporate OAuth, no external scripts, no `.ics`.** Google Calendar/Gmail are accessed only through a persistent Chromium session the user signs into (`persist:work-google`).
- **$0 operating cost.** Free-tier LLMs (Gemini Flash / Flash-Lite with the user's own key) plus deterministic local logic. All scheduling/nudge *detection* is deterministic and offline.
- **Low footprint.** Must not strain a work laptop: file-backed SQLite with a ~8 MB page cache, no embeddings, no local models, one hidden Google window at most.
- **No admin rights.** Per-user NSIS installer (`%LOCALAPPDATA%\Programs`), `requestedExecutionLevel: asInvoker`, `perMachine: false`. Nothing may require UAC (no machine-wide registry, services, or protocol handlers needing elevation). Start-at-login uses the per-user `app.setLoginItemSettings`.
- **Human-in-the-loop.** The assistant never writes a file, changes a task, or creates a draft without an Action Preview Card (`Apply / Edit / Dismiss`).

## 3. Storage Architecture

### 3.1 Vault (default `%USERPROFILE%\Desktop\NotesManager`, user-configurable)
The Desktop folder is backed up to Google Drive by Drive for Desktop (real local files, mirror-style, not streamed placeholders).

```
<Vault>/
  notes/2026/2026-11-13-nextmro-sync.md   # year-sharded; type/account in frontmatter
  inbox/2026-11.md                        # monthly rolling standalone-task inbox
  attachments/2026/<hash8>-name.png       # content-addressed, relative markdown links
  system/entities.json                    # curated registry ONLY
```

- **Year-sharded single tree.** Not account-grouped (accounts change, notes span several; moves = Drive delete+create and break references) and not type-split. Filename is *not* identity: frontmatter `id` (ULID) is. Collisions get `-2`.
- **Frontmatter is user-authored only:** `id, title, type (meeting|adhoc|inbox), date, account, attendees, calendar_event_id`, optional `classification: CUI` / `llm: off`. LLM-derived entities are **not** written back to files.
- **`entities.json`** = curated registry (people + aliases, accounts, systems, "Me"). Sorted keys, stable formatting, atomic writes. Derived data (`note_entities`, LLM suggestions, mention counts) lives only in SQLite; LLM finds go to a suggestions queue the user promotes into the registry. No periodic JSON export.
- **Machine-local (never in vault):** `userData/index.db`, `settings.json`, API keys (Electron `safeStorage`/DPAPI), `persist:work-google` session data.

### 3.2 Inline task syntax
`- [ ] Verify firewall rules | @Sarah | due:2026-11-17 | priority:High | est:30m ^t7k2`

- `^id` is a stable inline marker appended on first index; all write-backs locate the line by it. Checkbox lines are the single source of truth (the "action table" is a UI rendering, not a file format).
- `@Me` (case-insensitive, plus `meAliases`) = mine; everything else = Waiting On. `est:` optional (default 30 min). Relative dates are parsed locally (`chrono-node`, America/New_York).

### 3.3 Sync safety (Google Drive + Windows)
- **Index is idempotent and keyed on content hash** (`file_state`): our own writes re-hash identically, so echo loops are impossible by construction; a write ledger additionally drops our own watcher events.
- **Line-level patch writes with compare-and-swap:** re-read, verify hash, re-apply the single-line edit if a newer Drive copy arrived. Never rewrite a whole file from stale state. Temp file + rename in same directory (verify Drive ignores the temp name).
- **Windows locking:** retry with backoff on `EBUSY/EPERM/EACCES`; never hold handles open; sanitize slugs (reserved names, trailing dots, Unicode normalization); watch path length.
- **Partial/truncated reads:** on parse failure keep the previous index entry and retry after debounce.
- **Drive conflict copies** (`name (1).md`, "Conflict") are detected and shown in a Conflicts panel with a diff against the last-indexed snapshot.
- **Single active writer** assumed. Chokidar with `awaitWriteFinish`; polling fallback.

## 4. Database & IPC

- **`node:sqlite`** (`DatabaseSync`), WAL, `foreign_keys=ON`, `cache_size≈8MB`, `mmap_size=0`, numbered migrations via `PRAGMA user_version`. Schema in `src/main/db/migrations.ts` (✅ v1): `file_state, notes, tasks, entities, note_entities, note_chunks + chunks_fts (FTS5, porter), calendar_events, email_threads, nudges (unique dedupe_key), assistant_messages, llm_usage, llm_cache`. Differences from the original schema: ULID note ids, `inbox` type, `llm_blocked`, task `line_hash/est_minutes/assigned_at/is_mine`, `topic` entity category, `source` on `note_entities`.
- **Typed IPC (✅):** `src/shared/channels.ts` (plain name lists, preload-safe) + `src/shared/contract.ts` (zod input/output per channel, `Api` type). Main validates inputs *and* outputs; errors return `Result<T>`. Preload exposes only `window.api.invoke/on` with an allow-list (no raw `ipcRenderer`; `window.electron` removed). Window: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, navigation locked, single-instance lock.
- **All business logic in main-process services** (Vault, Indexer, Tasks, Entities, GoogleBridge, NudgeEngine, LlmRouter, Assistant). UI, Co-Pilot "Apply", and Quick-Capture call the same service methods: one write path.
- **Renderer:** CodeMirror 6 source-mode Markdown (task-line decorations; never round-trips/rewrites the file), Zustand + event invalidation, `cmdk`, `d3-force`/`d3-cloud`, custom calendar grid.

## 5. Google Workspace: OAuth first, private Apps Script second, no screen-reading

Superseded 2026-11-14 (decisions 59 to 62). The hidden-window scrapers (calendar agenda chips, Gmail grid, event click-through) and their parsers were deleted; they were slow, broke with Google UI changes and could not see Chat or Meet notes.

- **Ladder per section (calendar, mail, Meet notes, Chat):** official OAuth APIs (`google/oauth.ts`, `api.ts`, `connector.ts`) when connected, otherwise the user's own **Apps Script web app** (`google-bridge/Code.gs`, client `google/bridge.ts`), otherwise "signed out" with the last good data kept (`google/hub.ts`).
- **The bridge:** a read-only script the user pastes into their own Google account (Execute as: Me, Access: only myself). It uses the Calendar and Gmail advanced services plus Drive/Docs. Auth is the signed-in Google session cookies (`persist:work-google`, plain HTTPS `session.fetch`, nothing rendered) plus a random per-install token that the app substitutes into the copied script (`google:bridge-script`, token in the secret store). Responses are validated with zod; a version/contract handshake (`MIN_BRIDGE_VERSION`, `CONTRACT`), sign-in-redirect and admin-block detection, retry with jitter for network and timeouts only, and single-flight calls. Mail is incremental by Gmail history id. Calendar event ids match the web format, so notes keep linking. The script is bundled with `?raw`; its handlers run in Node `vm` tests against fake Google services.
- **Meet notes and transcripts:** matched to the exact meeting through the event's attached documents (`event_attachments`, migration 10), falling back to the title and time; written once per file id into the meeting note.
- **Chat:** complete only through OAuth with the Chat API enabled (all DMs, group chats, spaces, mentions, own messages). Through the bridge it is partial and the UI says so. See decision 60.
- **Setup and health:** Settings → Google shows a four-row card (Calendar, Mail, Meeting notes, Chat) with source, last sync and a plain state, plus a setup wizard (`BridgeSetup.tsx`): copy script, copy settings file, deploy, paste the address, Verify (ping and self-test per section). A failed sync never replaces good data.
- **Still visible windows (user acts in them):** sign-in (`openLogin`), reading an email thread, and the pre-filled compose window. Nothing is sent without the user.
- **Findings kept from the original spike:** Okta + 2FA/YubiKey sign-in works in the embedded session (daily re-auth is expected); the admin disables Gmail basic-HTML; at the user's workplace a Google Cloud project cannot be created, so OAuth waits on an IT-provided client while the bridge carries Calendar, Mail and Meet notes.

## 6. Proactive Executive Co-Pilot (deterministic rule engine)

60-second tick evaluates rules over SQLite; `nudges.dedupe_key` (e.g. `prep:<eventId>:<date>`) makes rules idempotent. On `powerMonitor` resume it catches up missed windows (a morning brief still appears if the app opens at 9:10). Work hours default 08:00–18:00 America/New_York. Needs tray + hide-on-close + start-at-login. **Zero LLM calls to decide *when* to nudge.**

| Rule | Logic |
|---|---|
| Morning brief (8:00) | Today's events, due/overdue tasks, Waiting-On items stale 3+ days |
| Pre-meeting prep (T-15m) | Match title/attendees to past notes; open tasks + unresolved questions |
| Post-meeting empty note (T+5m) | Ended 5 min ago and no linked note (by `calendar_event_id` or title/date) or body under threshold |
| Capacity overload | Meeting hours vs. open `@Me` task `est:` (default 30 min) in the window |
| Follow-up radar | `@WaitingOn` tasks past due/N days + sent email >48h without reply |
| Chronic blocker | Entity or normalized open-question text repeats across 3+ consecutive meetings in a series (recurring event id, else title + attendee overlap). Trigram/Jaccard similarity; optional LLM confirm |
| 4:45 PM end-of-day | Close-the-loop triage + deadline collisions (multiple High tasks same day / heavy meeting day) |

Chat (LLM): brain-dump → typed proposals (`create_note, create_task, update_task, set_reminder, draft_email`) rendered as Action Preview Cards. Dates: LLM returns the phrase; local `chrono-node` resolves, disagreements are flagged on the card. RAG: FTS5 bm25 over heading-level chunks + entity filters → top 5 chunks → Gemini Flash with chunk-id citations. No embeddings in v1.

## 7. LLM Router & Data Policy

- **Policy (2026-11-14, decision 63):** no content restrictions. Nothing is blocked, withheld or redacted before it goes to the user's own provider; there is no CUI detection, no never-send list and no per-note block. The spend controls remain (mode, daily token budget, provider order). The `notes.llm_blocked` column is kept for schema stability and always 0.
- **Providers (all bring-your-own-key, each can be switched on/off and re-ordered):** Gemini (REST, JSON MIME), Groq / OpenRouter / OpenAI (chat-completions dialect, `json_object`), Anthropic Claude (Messages API). Default order Gemini → Groq → OpenRouter → OpenAI → Anthropic. See decision 35.
- **Tiers:** `extract` (small model) and `chat/rag` (larger model) per provider; model names are overridable in Settings.
- **Reliability:** per-provider token buckets (RPM/RPD) persisted in `llm_usage`; circuit breaker on 429/5xx honoring `Retry-After`; automatic failover; zod validation + one repair retry; response cache `llm_cache` by `hash(tier+prompt)`.
- **Enrichment queue:** runs after ~30 s idle and only when the content hash changed.
- **Keys:** `safeStorage` (DPAPI) in `userData`, never in the vault.

## 8. Feature Modules (unchanged intent, updated mechanics)

1. **Notes:** meeting template (Context & Objective / Key Decisions / Open Questions / Action Items) and ad-hoc notes; same inline task syntax.
2. **Master Task View:** group/filter by account, owner (Mine vs Waiting On), due bucket, source note; quick-add → `inbox/YYYY-MM.md`; toggling patches the single line by `^id`. **Waiting-On tracker** shows days since `assigned_at` and a "Draft follow-up" button.
3. **Entities & analytics:** deterministic pass (registry + `@mentions`/`#tags`) instantly; LLM enrichment async into SQLite; entity dossier; word map + co-occurrence graph over a date range.
4. **Calendar view + Prep dossier:** past notes, upcoming events (from `calendar_events`), due badges; click a future event → pre-filled meeting note; prep sheet = attendee/account open tasks + prior unresolved questions + recent flagged email subjects.
5. **Comms:** recap/reply drafter → Gmail compose window (v1) or clipboard (Chat/Gmail formatting).
6. **Extras:** `Ctrl+Shift+Space` quick-capture (pre-created hidden always-on-top window; key configurable), `Ctrl+K` command palette, Friday weekly rollup, `Ctrl+J` Co-Pilot drawer.

## 10. Decision Log (2026-11-13)

1. LLM use unrestricted except CUI-labeled content (hard block).
2. Okta password + 2FA/YubiKey; daily re-login accepted; spike first.
3. Vault = Desktop folder backed up by Drive; mirror-style local files; single writer.
4. Year-sharded `notes/YYYY/`, type in frontmatter.
5. `node:sqlite` primary; `sql.js` removed (it holds the whole DB in RAM, the opposite of the low-memory requirement).
6. Tray, hide-on-close, start-at-login enabled.
7. CodeMirror 6 source-mode editor.
8. Work hours 08:00–18:00 America/New_York; `est:` optional, default 30 min.
9. "Me" identity = `@Me` (aliases configurable).
10. Gmail drafts v1 = visible prefilled compose window.
11. Installer must be per-user, no-admin NSIS.
12. **UI/UX (2026-11-13):** one **New note** action (no meeting/note choice); meetings come from the calendar via a **Meetings** tab and a click opens-or-creates the pre-filled note (idempotent via `calendar_event_id`); **Notes** tab groups by recency. Blank notes are created instantly as "Untitled" with the title field focused; naming it renames the file. Frontmatter is hidden and protected in the editor (header shows title/date). Footer shows sync status + refresh; Settings (gear) holds theme, Google connection, notes folder, technical details. Shortcut: `Ctrl+N`.
13. **Theme:** System / Light / Dark (default System), semantic CSS-variable tokens (`bg-app`, `text-muted`, …) so components need no per-element dark rules; `.dark` on `<html>`, applied before first paint; native chrome synced via `nativeTheme`. Preference stored in renderer `localStorage`.
14. **Diagnostics:** the temporary Google probe buttons and DOM dump code were removed; the Settings page keeps a collapsed Technical details section.
15. **Glass UI (2026-11-13):** frosted-glass panels (`.glass`: translucent fill + 28px backdrop blur + bright edge + soft shadow) floating over a gradient-mesh background; sidebar and main pane are separate rounded cards; primary actions use a gradient button. CSS-only (no native Mica/Acrylic) so it behaves identically in both themes. Tokens: `--glass`, `--glass-border`, `--glass-shadow`, `--mesh`, plus translucent `--field/--surface/--hover/--sticky`.
16. **Waiting time:** a delegated task's age counts from the earlier of the note's date and when we first saw it; for inbox tasks (file dated the 1st of the month) from when it was added, in local time.
17. **Tasks navigation:** Meetings | Notes | Tasks tabs in the sidebar; Tasks tab lists smart filters, main pane shows the list. Inbox files are hidden from the Notes tab (their tasks live in Tasks; a task's source link still opens them).
18. **Who is "me":** `settings.meAliases` (default `Me`) plus names learned automatically from the calendar (the RSVP line on every chip, needs 3+ sightings) on first sync, only while the user hasn't set their own. Editable in Settings → About you. Drives task ownership (`@Me`/`@Jacob` = mine, others = Waiting On) and keeps the user out of People. Changing it re-derives the whole index.
19. **Entity rules:** name match is case-insensitive and unique across categories (`idx_entities_lname`); a registry entry always wins over a discovered one; discovered entities with no notes are pruned, registry entries are kept even at zero mentions; Drive conflict copies are excluded from all analytics. An attendee is treated as "me" if any word of their name is one of my names.
20. **Chart palette (validated with the dataviz script, 2026-11-13):** categorical slots 1-3 only (blue `#2a78d6`/`#3987e5`, orange `#eb6834`/`#d95926`, aqua `#1baf7a`/`#199e70`) pass all-pairs CVD and normal-vision gates in both modes; light-mode contrast WARN on orange/aqua is covered by mandatory direct labels, per-category shapes and a table view. Four categories → topics use neutral `--muted` (+ a distinct shape). Single-series charts use slot 1.
21. **Gmail rules learned the hard way:** `-in:chats` in a search makes Gmail return nothing; `%20` and `+` both work in hash searches; sent rows list participants oldest→newest with "me" marked (threads with only me show no recipient); row participants are `span[email]` (not under a fixed cell class); rows can exist as empty skeletons before text paints, so readiness = a row with subject text. Time cell title format `Fri, Nov 13, 2026, 10:47 AM` (may use narrow-nbsp before AM/PM).
22. **Email privacy:** Gmail metadata is local only (`userData/index.db`), never in the vault, never sent to an LLM. Master switch `settings.gmailEnabled` (Settings → Gmail follow-ups). Threads untouched for 30 days (and not starred) are dropped. "Needs a reply" is a heuristic (last participant is me); it can't know a reply isn't expected, hence Dismiss.

25. **Relevance principle:** mail you *routed* (star, a label you created, a reply you wrote) is a signal; mail that merely *arrived* (bulk, automated, archived unseen) is noise. 90. **The assistant has a face.** The Co-Pilot header shows a large live portrait (name and a mood line under it); the Quick/Standard/Detailed switch sits by the chat box; the conversation only follows new text while you are at the bottom ("Jump to latest" otherwise). A pure mood machine (`shared/avatarMood.ts`: idle, listening, thinking, talking, happy, concerned, surprised, sleepy, waking) drives breathing, random blinks, pointer-following eyes, mood faces and per-persona signature moves (Nova's orbiting sparkle, Pip's hop, Sage's glasses and beard, Rook's arched brow), each with a cool-down; reduced motion turns it all off.
91. **Setup guide.** State lives in the guide, so nothing typed is lost between steps; a pasted AI key is saved and tested on its own with live states and a persistent "Connected: <provider>" badge; a live checklist (Notes Folder, Your Name, Google, AI) ticks as you go; steps slide in the direction you move, content cascades in, and finishing plays confetti.
92. **One company Google sign-in.** The per-user Client ID / secret fields and "create a project" steps are gone. IT creates one Internal Desktop OAuth client once (`docs/IT-GOOGLE-SIGN-IN.md`); `build/google-client.json` (git-ignored, excluded from the package) is baked into the main bundle at build; colleagues only press Sign In With Google. `npm run build:win` fails without it; `npm run build:win:script-only` builds a personal, script-only installer on purpose. `NM_GOOGLE_CLIENT_ID` works only in development and tests.
93. **The assistant converses and looks things up.** Every chat message goes to an agent (`assistant/agent.ts`): each turn the model either answers or asks for up to three read-only lookups (`assistant/tools.ts`: notes, one note in full, your tasks, Waiting On, calendar with guests, a person or topic with their history, inbox insights, email subjects, one email's text in memory when allowed, chat). A simple question is one call; Standard allows two rounds of lookups, Detailed four, Quick none (one call over pre-gathered context). The reply says what it looked at ("Looked at your calendar and Priya."), cites notes, and renders light formatting (bold, bullets, numbered lists; never HTML). If AI is unavailable, or fails on the first call, the older rule-based answers run. Casual or list-like messages are not forced into capture: the model replies in its own voice and, for a pile of to-dos, offers a "Turn these into tasks" button that runs the existing capture and card approval (`/note` still goes straight to capture). Conversation memory is 2 / 6 / 12 turns (Quick / Standard / Detailed).
94. **Personalities are character sheets.** Each persona has a full voice description (how they talk, what they notice, opinions, what they never do) used on every reply, and a two-sentence version in Quick mode (`shared/personas.ts`). The automatic messages (morning brief, meeting prep, overdue, reply owed, end of day) are still triggered and fact-gathered by rules, but the text is written by the model from those facts in the persona's voice (a small call, cached, at most 12 a day), with the fixed phrases as the fallback. One-click chips use the model whenever a key works (the rule-based answers are the fallback, with a "Polish with AI" button), and their prompts ask for a view, not a neutral list; the day brief now includes guests, what people owe you, replies owed and new insights.
95. **Missing @ and # are written as you type.** "Tell Matt he likes cats" becomes "Tell @Matt he likes #cats". `@` marks any named thing in your lists (people, companies, projects, systems, places; the registry knows which kind) and `#` marks a topic; multi-word names keep their words (`@Sarah Chen`, and the extractor now reads `@` plus a known longer name as that one entity). The engine is pure (`shared/autotag.ts`) and tags only the word just finished: the editor does it at a space, punctuation or Enter (`editor/autotag.ts`, each tag its own undo step, so one Ctrl+Z puts the plain word back, and a tag you take off is added to a never-tag list in Settings), quick capture and Co-Pilot cards do it on submit (after quick-add's parse, because that parser takes the first `@word` as the owner). It never touches existing text on open, code, links, URLs, emails, frontmatter, a task's `| @owner | due:` fields, your own names, names marked ambiguous (those go to Review People), or everyday words. Known topics (used in at least two notes) are tagged instantly and offline; with AI on, a small model also suggests up to two new topics and three new names after you finish a line (`assistant/autotag.ts`), every suggestion must be exact words of the line, new names are added to your lists first, and it is rate-limited (12 a minute, 300 a day). Without AI, a capitalised name after a verb ("Tell / ask / waiting on …") is tagged and learned. Settings has an Auto-Tagging section; "Auto-Tag This Note" in the palette tags an older note with an undo toast.
96. **Auto-tagging leans toward too many tags, and shared names are reviewed, not skipped.** A first name shared by two people ("Priya"), or a name marked ambiguous, is still tagged (`@Priya`) and waits in Review People (the Knowledge sidebar shows the count; the editor says so when it happens). Such a tag links to nobody until you assign it (frontmatter `mentions`), and it never invents a plain "Priya" person (the matcher treats unclaimed shared first names as ambiguous; an explicit alias or full name in your lists always wins). Your own names are still never tagged. To lean toward more tags: every topic you have used once is tagged (not two notes), the model may add up to four topics and five names per line, its prompt says a missed tag costs more than an extra one, lines of 8 characters or more are considered, and more verb cues are recognised ("with / from / by / for / to" plus a capitalised name). Auto-tagging is the lowest-priority user of the AI: it makes at most 6 calls a minute and 200 a day, and only when the provider has at least five calls a minute left for the Co-Pilot.
97. **Auto-tagging without AI, and review beyond people.** With AI off, new names are still found from the words around them and given the right kind: "with Globex Corp" or "client Initech" (company), CamelCase or "using Okta" (system), "the Zephyr project" (project), "in Lisbon" (place), "Tell Rhea" (person). Names that share a first word across any kind ("Acme Corp" and "Acme Portal") are tagged and wait in Knowledge → Review Names (renamed from Review People); a new name added there takes the kind of the others. Known topics are still the only topics found without AI.
98. **A task is always mine; people and things are "involved".** Quick capture, Co-Pilot cards and wording ("Remind Sarah to…") never change a task's owner. An `@Name` (including `@John Smith`) stays in the task as a tag and the task lists what it is about (people, companies, places, projects, systems) as chips, with an About filter in Tasks. Waiting On is only made by typing "waiting on Sarah: …". Co-Pilot turns "Sarah should send the deck" into "Follow up with Sarah: send the deck". Insights from meetings/email where someone else owes you still become Waiting On lines.
99. **Smarter, cheaper auto-tagging.** Built-in lists of places and well-known software, companies read from email-sender domains, and a memory of kinds you corrected (Manage → recategorize) classify names without AI. Weak guesses ("with Zorblax", "in Kralupy") are maybe-tags: dotted underline, Tab writes it, Esc ignores it. Knowledge → Review Names has Suggested Tags: capitalised names in 3+ notes and uncommon words in 4+ notes, counted locally (Add as a kind, or Ignore). The model is asked only when the rules left a capitalised unknown word or an uncommon word; Settings shows "AI calls today" (cap 120).
100. **Meeting Series.** Tasks → Meeting Series groups meetings with the same normalised title (calendar events and meeting notes, two or more sessions). Sessions stay independent notes; the page is derived: sessions with status, carried-forward unticked actions, open questions from the last three sessions, a decisions log, and Start Next Session (the next calendar event's note, or a new one, with what is still open listed under "Carried Forward From Last Time").
101. **Series by hand, by Google, and by topic.** A meeting note can be added to or removed from a series by hand (frontmatter `series: "Title"`, "-" means none; the file stays the source of truth). When the calendar gives Google's repeat id (Apps Script bridge: re-copy the script; older scripts still work, without it), occurrences with different titles join one series. The page lists Topic Threads (people, companies, projects, systems and topics that come up in two or more sessions, with the lines that mention them) and Create Master Page (a normal note with the sessions, decisions log, open questions and what is still open, as a snapshot). Not done: embedded sub-notes.
102. **Name kinds are voted, and Tag Health.** A name's kind is decided by all its mentions across your notes (for example "the Zorblax contract" twice beats one "with Zorblax"), once two or more agree; what you recategorised still wins. Settings → Auto-Tagging has Tag Health: tags kept, accepted with Tab and taken off, and the words taken off most, with Allow again. Events are stored in `tag_events`.
