# Product & Technical Specification: notes-manager

Local-first desktop notes + task tracker for Technical Delivery Management. Meeting notes and action items live in one workspace. **Revision 2 (2026-11-13)** supersedes the original spec: the Google Apps Script / `/Bridge` dead-drop and `.ics` approaches are removed; Google Workspace integration uses an isolated Electron session instead.

Status legend: ✅ done · 🔜 next · ⬜ planned

---

## 1. Principles & Constraints

- **Local-first, human-readable.** Notes are Markdown with YAML frontmatter in a vault folder. SQLite is a *disposable derived index*: deleting it loses nothing.
- **No corporate OAuth, no external scripts, no `.ics`.** Google Calendar/Gmail are accessed only through a persistent Chromium session the user signs into (`persist:work-google`).
- **$0 operating cost.** Free-tier LLMs (Gemini Flash / Flash-Lite with the user's own key) plus deterministic local logic. All scheduling/nudge *detection* is deterministic and offline.
- **Low footprint.** Must not strain a work laptop: file-backed SQLite with a ~8 MB page cache, no embeddings, no local models, one hidden Google window at most.
- **No admin rights.** Per-user NSIS installer (`%LOCALAPPDATA%\Programs`), `requestedExecutionLevel: asInvoker`, `perMachine: false`. Nothing may require UAC (no machine-wide registry, services, or protocol handlers needing elevation). Start-at-login uses the per-user `app.setLoginItemSettings`.
- **Human-in-the-loop.** The assistant never writes a file, changes a task, or creates a draft without an Action Preview Card (`Apply / Edit / Dismiss`).

## 3. Storage Architecture

### 3.1 Vault (default `%USERPROFILE%\Desktop\NotesManager`, user-configurable)
The Desktop folder is backed up to Google Drive by Drive for Desktop (real local files, mirror-style, not streamed placeholders).

```
<Vault>/
  notes/2026/2026-11-13-nextmro-sync.md   # year-sharded; type/account in frontmatter
  inbox/2026-11.md                        # monthly rolling standalone-task inbox
  attachments/2026/<hash8>-name.png       # content-addressed, relative markdown links
  system/entities.json                    # curated registry ONLY
```

- **Year-sharded single tree.** Not account-grouped (accounts change, notes span several; moves = Drive delete+create and break references) and not type-split. Filename is *not* identity: frontmatter `id` (ULID) is. Collisions get `-2`.
- **Frontmatter is user-authored only:** `id, title, type (meeting|adhoc|inbox), date, account, attendees, calendar_event_id`, optional `classification: CUI` / `llm: off`. LLM-derived entities are **not** written back to files.
- **`entities.json`** = curated registry (people + aliases, accounts, systems, "Me"). Sorted keys, stable formatting, atomic writes. Derived data (`note_entities`, LLM suggestions, mention counts) lives only in SQLite; LLM finds go to a suggestions queue the user promotes into the registry. No periodic JSON export.
- **Machine-local (never in vault):** `userData/index.db`, `settings.json`, API keys (Electron `safeStorage`/DPAPI), `persist:work-google` session data.

### 3.2 Inline task syntax
`- [ ] Verify firewall rules | @Sarah | due:2026-11-17 | priority:High | est:30m ^t7k2`

- `^id` is a stable inline marker appended on first index; all write-backs locate the line by it. Checkbox lines are the single source of truth (the "action table" is a UI rendering, not a file format).
- `@Me` (case-insensitive, plus `meAliases`) = mine; everything else = Waiting On. `est:` optional (default 30 min). Relative dates are parsed locally (`chrono-node`, America/New_York).

### 3.3 Sync safety (Google Drive + Windows)
- **Index is idempotent and keyed on content hash** (`file_state`): our own writes re-hash identically, so echo loops are impossible by construction; a write ledger additionally drops our own watcher events.
- **Line-level patch writes with compare-and-swap:** re-read, verify hash, re-apply the single-line edit if a newer Drive copy arrived. Never rewrite a whole file from stale state. Temp file + rename in same directory (verify Drive ignores the temp name).
- **Windows locking:** retry with backoff on `EBUSY/EPERM/EACCES`; never hold handles open; sanitize slugs (reserved names, trailing dots, Unicode normalization); watch path length.
- **Partial/truncated reads:** on parse failure keep the previous index entry and retry after debounce.
- **Drive conflict copies** (`name (1).md`, "Conflict") are detected and shown in a Conflicts panel with a diff against the last-indexed snapshot.
- **Single active writer** assumed. Chokidar with `awaitWriteFinish`; polling fallback.

## 4. Database & IPC

- **`node:sqlite`** (`DatabaseSync`), WAL, `foreign_keys=ON`, `cache_size≈8MB`, `mmap_size=0`, numbered migrations via `PRAGMA user_version`. Schema in `src/main/db/migrations.ts` (✅ v1): `file_state, notes, tasks, entities, note_entities, note_chunks + chunks_fts (FTS5, porter), calendar_events, email_threads, nudges (unique dedupe_key), assistant_messages, llm_usage, llm_cache`. Differences from the original schema: ULID note ids, `inbox` type, `llm_blocked`, task `line_hash/est_minutes/assigned_at/is_mine`, `topic` entity category, `source` on `note_entities`.
- **Typed IPC (✅):** `src/shared/channels.ts` (plain name lists, preload-safe) + `src/shared/contract.ts` (zod input/output per channel, `Api` type). Main validates inputs *and* outputs; errors return `Result<T>`. Preload exposes only `window.api.invoke/on` with an allow-list (no raw `ipcRenderer`; `window.electron` removed). Window: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, navigation locked, single-instance lock.
- **All business logic in main-process services** (Vault, Indexer, Tasks, Entities, GoogleBridge, NudgeEngine, LlmRouter, Assistant). UI, Co-Pilot "Apply", and Quick-Capture call the same service methods: one write path.
- **Renderer:** CodeMirror 6 source-mode Markdown (task-line decorations; never round-trips/rewrites the file), Zustand + event invalidation, `cmdk`, `d3-force`/`d3-cloud`, custom calendar grid.

## 5. Google Workspace via `persist:work-google`

- **Login:** visible window on first run and whenever the session expires (daily re-auth expected: Okta password + 2FA/YubiKey). Strip `Electron/` from the UA. WebAuthn/YubiKey support is verified in the M0.5 spike.
- **Isolation:** no preload, `nodeIntegration` off, `sandbox` on, `backgroundThrottling: false`; extraction only via `executeJavaScript` returning plain data. Session data lives in `userData`.
- **Calendar sync (✅ built, `src/main/calendar/` + `services/google.ts`):** hidden `BrowserWindow` loads the agenda; extraction reads `[role=rowgroup][data-datekey] [data-eventid]` chips. Date = decoded `data-datekey` (`((year-1970)<<9)|(month<<5)|day`); chip `innerText` lines = `time` / `title` / `Name, Status` (the chip has **no** `aria-label`). Parsing is pure and tested (`parse.ts`): time ranges with shared am/pm, RSVP status, kind (`meeting | task | working_location | allday`), dedupe of the double-rendered chips. Store (`sync.ts`): upsert, remove cancelled events inside the scraped date window, **never delete on an empty scrape**. Times are naive local (calendar's own timezone). Sync runs 2 s after launch, every 15 min, and on the manual Refresh button; concurrent calls share one run. Session expiry (redirect away from `calendar.google.com`) → state `needs-auth`, data kept, UI shows Reconnect; closing the sign-in window triggers an immediate re-sync. **Not yet:** attendees and Meet links (need event-detail click-through, M5 prep dossier); Gmail (M4 remainder).
- **Gmail sync:** standard-UI scraping of the visible grid (basic-HTML is admin-disabled, see go/no-go above); scan starred/flagged threads and sent mail >48h with no reply → `email_threads`.
- **Drafts (v1): visible prefilled compose window** (`?view=cm&fs=1`), user clicks Save/Send; clipboard fallback for long bodies. v2 experiment: hidden window + injected body + autosave.
- **Go/no-go: PASSED (2026-11-13).** Okta password + 2FA/YubiKey sign-in works in the embedded `persist:work-google` session; Calendar agenda and Gmail were both readable from a hidden window. Findings that shape M4:
  - **Calendar:** `[data-eventid]` yields ~2 DOM nodes per event (82 nodes, 39 unique ids): **dedupe by `data-eventid`**. Non-meeting entries are separable from the `aria-label` text: `Working location`, `task:` / `Calendar: Tasks`, `Declined`, `All day`; the rest are timed events. Store Declined for reference but exclude from prep/overload logic. The agenda markup does **not** include Meet URLs: fetch the join link from the event detail (click-through) only for events within the next ~24 h.
  - **Gmail:** the admin **disables the basic-HTML view** (redirects to `#inbox`), so the standard UI is scraped instead: `tr[role="row"]` rows expose thread id (`[data-thread-id]`/`[data-legacy-thread-id]`), sender, subject (`.bog`), time (`.xW`) and unread (`.zE`) at 100% coverage on inbox, starred and sent. Gmail keeps previously visited views in the DOM, so per-view counts from one window were cumulative: **scope extraction to the visible grid only** (`offsetParent !== null`) and navigate with `#inbox` / `#starred` / `#sent` / `#search/...`.
  - **Labels (decided, M4):** mail filtered out of the inbox (Calendar invites, Jira, CHIRPS, etc.) is handled **without opening each label**. (1) One read of the left-nav gives every label + unread count, so labels are discovered dynamically; (2) one or two Gmail searches (e.g. `in:anywhere newer_than:2d`, `is:unread -in:sent`) return mail across all labels in a single grid whose rows carry label chips. Settings map **label → handler**: `ignore | count-only (brief) | mine-only | tasks+nudges+reminders`. Handlers are deterministic (e.g. Jira issue keys from subjects, assigned/mentioned-me heuristics, dedupe by thread id); suggested tasks go through the Action Preview Card, never auto-created. Calendar-invite labels are not content-scanned (Calendar is the source of truth). Validate chip visibility vs. Gmail display density in M4.
  - Re-auth is still expected daily; detect it by the final URL leaving `calendar.google.com` / `mail.google.com`.

## 6. Proactive Executive Co-Pilot (deterministic rule engine)

60-second tick evaluates rules over SQLite; `nudges.dedupe_key` (e.g. `prep:<eventId>:<date>`) makes rules idempotent. On `powerMonitor` resume it catches up missed windows (a morning brief still appears if the app opens at 9:10). Work hours default 08:00–18:00 America/New_York. Needs tray + hide-on-close + start-at-login. **Zero LLM calls to decide *when* to nudge.**

| Rule | Logic |
|---|---|
| Morning brief (8:00) | Today's events, due/overdue tasks, Waiting-On items stale 3+ days |
| Pre-meeting prep (T-15m) | Match title/attendees to past notes; open tasks + unresolved questions |
| Post-meeting empty note (T+5m) | Ended 5 min ago and no linked note (by `calendar_event_id` or title/date) or body under threshold |
| Capacity overload | Meeting hours vs. open `@Me` task `est:` (default 30 min) in the window |
| Follow-up radar | `@WaitingOn` tasks past due/N days + sent email >48h without reply |
| Chronic blocker | Entity or normalized open-question text repeats across 3+ consecutive meetings in a series (recurring event id, else title + attendee overlap). Trigram/Jaccard similarity; optional LLM confirm |
| 4:45 PM end-of-day | Close-the-loop triage + deadline collisions (multiple High tasks same day / heavy meeting day) |

Chat (LLM): brain-dump → typed proposals (`create_note, create_task, update_task, set_reminder, draft_email`) rendered as Action Preview Cards. Dates: LLM returns the phrase; local `chrono-node` resolves, disagreements are flagged on the card. RAG: FTS5 bm25 over heading-level chunks + entity filters → top 5 chunks → Gemini Flash with chunk-id citations. No embeddings in v1.

## 7. LLM Router & Data Policy

- **Policy:** no restriction on LLM use *except* content labeled CUI. A note with `classification: CUI` (or tag `#cui`, or `llm: off`) is flagged `llm_blocked` and is **never** sent to any provider, including as RAG context or enrichment input. Also never send calendar/Gmail-scraped content when it matches a CUI-labeled note's account. Global kill-switch `settings.llm.enabled`; everything degrades to deterministic behavior when off/offline.
- **Providers (all bring-your-own-key, each can be switched on/off and re-ordered):** Gemini (REST, JSON MIME), Groq / OpenRouter / OpenAI (chat-completions dialect, `json_object`), Anthropic Claude (Messages API). Default order Gemini → Groq → OpenRouter → OpenAI → Anthropic. See decision 35.
- **Tiers:** `extract` (small model) and `chat/rag` (larger model) per provider; model names are overridable in Settings.
- **Reliability:** per-provider token buckets (RPM/RPD) persisted in `llm_usage`; circuit breaker on 429/5xx honoring `Retry-After`; automatic failover; zod validation + one repair retry; response cache `llm_cache` by `hash(tier+prompt)`.
- **Enrichment queue:** runs after ~30 s idle and only when the content hash changed.
- **Keys:** `safeStorage` (DPAPI) in `userData`, never in the vault.

## 8. Feature Modules (unchanged intent, updated mechanics)

1. **Notes:** meeting template (Context & Objective / Key Decisions / Open Questions / Action Items) and ad-hoc notes; same inline task syntax.
2. **Master Task View:** group/filter by account, owner (Mine vs Waiting On), due bucket, source note; quick-add → `inbox/YYYY-MM.md`; toggling patches the single line by `^id`. **Waiting-On tracker** shows days since `assigned_at` and a "Draft follow-up" button.
3. **Entities & analytics:** deterministic pass (registry + `@mentions`/`#tags`) instantly; LLM enrichment async into SQLite; entity dossier; word map + co-occurrence graph over a date range.
4. **Calendar view + Prep dossier:** past notes, upcoming events (from `calendar_events`), due badges; click a future event → pre-filled meeting note; prep sheet = attendee/account open tasks + prior unresolved questions + recent flagged email subjects.
5. **Comms:** recap/reply drafter → Gmail compose window (v1) or clipboard (Chat/Gmail formatting).
6. **Extras:** `Ctrl+Shift+Space` quick-capture (pre-created hidden always-on-top window; key configurable), `Ctrl+K` command palette, Friday weekly rollup, `Ctrl+J` Co-Pilot drawer.

16. **Waiting time:** a delegated task's age counts from the earlier of the note's date and when we first saw it; for inbox tasks (file dated the 1st of the month) from when it was added, in local time.
17. **Tasks navigation:** Meetings | Notes | Tasks tabs in the sidebar; Tasks tab lists smart filters, main pane shows the list. Inbox files are hidden from the Notes tab (their tasks live in Tasks; a task's source link still opens them).
18. **Who is "me":** `settings.meAliases` (default `Me`) plus names learned automatically from the calendar (the RSVP line on every chip, needs 3+ sightings) on first sync, only while the user hasn't set their own. Editable in Settings → About you. Drives task ownership (`@Me`/`@Jacob` = mine, others = Waiting On) and keeps the user out of People. Changing it re-derives the whole index.
19. **Entity rules:** name match is case-insensitive and unique across categories (`idx_entities_lname`); a registry entry always wins over a discovered one; discovered entities with no notes are pruned, registry entries are kept even at zero mentions; Drive conflict copies are excluded from all analytics. An attendee is treated as "me" if any word of their name is one of my names.
20. **Chart palette (validated with the dataviz script, 2026-11-13):** categorical slots 1-3 only (blue `#2a78d6`/`#3987e5`, orange `#eb6834`/`#d95926`, aqua `#1baf7a`/`#199e70`) pass all-pairs CVD and normal-vision gates in both modes; light-mode contrast WARN on orange/aqua is covered by mandatory direct labels, per-category shapes and a table view. Four categories → topics use neutral `--muted` (+ a distinct shape). Single-series charts use slot 1.
21. **Gmail rules learned the hard way:** `-in:chats` in a search makes Gmail return nothing; `%20` and `+` both work in hash searches; sent rows list participants oldest→newest with "me" marked (threads with only me show no recipient); row participants are `span[email]` (not under a fixed cell class); rows can exist as empty skeletons before text paints, so readiness = a row with subject text. Time cell title format `Fri, Nov 13, 2026, 10:47 AM` (may use narrow-nbsp before AM/PM).
22. **Email privacy:** Gmail metadata is local only (`userData/index.db`), never in the vault, never sent to an LLM. Master switch `settings.gmailEnabled` (Settings → Gmail follow-ups). Threads untouched for 30 days (and not starred) are dropped. "Needs a reply" is a heuristic (last participant is me); it can't know a reply isn't expected, hence Dismiss.
23. **Sync cadence:** calendar 15 min (first run +2 s), Gmail 20 min (first run +6 s), both on the Refresh button and right after the sign-in window closes. One shared Google session; either bouncing to SSO shows "Not connected" and keeps existing data.
24. **All Mail over per-label searches (2026-11-13):** one crawl is faster (one page load + hash paging) and richer (every row carries star state, participants, and label chips). A search containing `-in:chats` returns nothing; `-category:*` negations work and remove bulk mail at the source. Gmail ignores synthetic `click()` on the Older button, but changing `location.hash` to `…/pN` pages reliably. Mail volume is high (~1,700 conversations in 30 days on the test mailbox), so storage is metadata-only and retention is 100 days by message date (starred kept).
25. **Relevance principle:** mail you *routed* (star, a label you created, a reply you wrote) is a signal; mail that merely *arrived* (bulk, automated, archived unseen) is noise. A label you made keeps even automated mail (Jira). Muting beats everything except a star. Stored rows are never discarded by the filter, so changing a handler or unmuting restores mail without re-crawling.
26. **Auto-tagging is deterministic now, LLM later (M7):** rules are conservative phrasings, not guesses. Talking *about* someone stays yours ("Call Sarah", "Ask Sarah about…"); only delegation phrasings reassign. Common-word first names (Will, Mark, May…) and ambiguous first names are never matched alone. `Me` names always win. New people join the tagging pool without typing `@`: from emails sent to/from you, earlier mentions, attendees, and the registry.
27. **Detected values are never written into your files.** Inferred owners/dates live only in the index (`tasks.auto_owner/auto_due`) and are re-derived on every index; typing an explicit field makes it permanent and removes the ✦. Quick-add writes `@owner` only if you typed one (or it isn't you).
28. **Nudge discipline:** a nudge fires only when it is *actionable and has context*. Prep needs an earlier note in the series; capture needs a note-taking habit (or a long meeting); the radar is one digest, not one nudge per item; the brief catches up within 4 h of work start but not later. Everything stays visible in the feed even outside work hours; toasts are limited to weekdays inside work hours (-15 min / +90 min). Calendar times are treated as local (same timezone as the calendar).
29. **Background running:** closing the window hides it to the tray (setting, default on) so the scheduler keeps ticking; Quit lives in the tray menu. Start-at-login passes `--hidden` so the app boots to the tray without a window; it is only registered for the packaged app. Neither needs administrator rights. A sleeping laptop is handled by `powerMonitor` resume, not by cron.
30. **Not verified in this environment:** a real Windows toast on screen (no interactive desktop in the test session). The code path runs without error and the Settings "Send a test notification" button exercises it on the user's machine. Toasts from the installed per-user build use the Start Menu shortcut's AppUserModelID (`com.notesmanager.app`).
31. **Attendees are fetched lazily, never in bulk.** The agenda page has no guest data and one detail page costs several seconds, so the app loads a meeting's guests only when you open its prep sheet (and caches them). The "not fetched" state is distinct from "no guests" (`detail_at`). Your own address (learned from Gmail) and room/resource calendars are dropped. Guest names are rarely shown by Google, so names come from emails you have exchanged, then the address (`jane.doe@x.com` → "Jane Doe").
32. **Prep nudges point at the prep sheet.** The T-15 nudge's first button is now "Prep sheet" (then "Open meeting notes" and "Last notes").
33. **The Co-Pilot proposes; the user decides.** Every model answer is schema-validated, capped (3 notes, 8 tasks, 5 reminders per message) and shown as an editable card. Dates are never trusted from the model: it returns the words ("next Thursday"), the app computes the day. Reminders without a usable future time stay on the card until one is picked.
34. **Free-tier keys are the user's own** and live only in `userData/secrets.json`, encrypted for the signed-in Windows user. Model names are overridable in settings (`llm.models`) because free-tier model names change. Free tiers may use submitted text to improve products, so the privacy box in Settings says what is sent (typed text, short note snippets) and what never is (CUI, email, addresses/numbers).
35. **Bring your own key, any of five providers.** Gemini, Groq, OpenRouter (free tiers) and OpenAI, Anthropic (paid, labelled as billing the user's own account). Each provider has its own switch, key, model names and position in the try-order; a switched-off provider keeps its key but is never called (its Test button still works). Keys are encrypted per Windows user; nothing is bundled or shared. **Usage display:** the app counts its own requests/tokens/failures per provider (today and last minute); OpenAI, Groq and Anthropic also report remaining requests/tokens for their current rate-limit window in response headers, which is shown with its age. Gemini and OpenRouter do not report quota to API keys, so only the local count is shown. These are rate-limit windows, not billing balances. **Subscriptions (Gemini Advanced / Google AI Pro, ChatGPT Plus, Claude Pro) do not include API access and are not used**; automating their web sessions would be fragile and against their terms. Pasting a new key clears any cooldown immediately.
36. **Capture and palette are local-first.** Neither calls an LLM: quick capture uses the deterministic parser, the palette searches in memory. The Co-Pilot (Ctrl+J) stays the place for brain-dumps. `NM_SHOW_CAPTURE=1` is a test-only hook that shows the capture window at startup.
37. **Tidy this note (Ctrl+K → "Tidy this note with the Co-Pilot").** Sends the open note's body (never its frontmatter) to the Co-Pilot as a brain-dump and shows a card for a NEW structured note; the original is never overwritten. Notes mentioning or tagged CUI are refused before anything is sent.
38. **Notes are never removed by the app.** Notes are files; the app only creates, edits and renames them, never deletes. The index is disposable and rebuilt from the files. Only derived data ages out: nudges after 30 days, Gmail metadata after 100 days (starred kept), and a cancelled calendar event leaves the agenda (any note taken for it stays). The All notes page has no date cut-off.
39. **All notes page (Notes tab, Ctrl+K "All notes").** Six views over the same notes, chosen with a sliding-pill switcher and a directional slide/fade (disabled under reduced-motion): Newest, Weeks (Monday-first), Meetings (recurring series grouped by title with dates stripped; one-offs together), Accounts, People & things (a note appears under everything it mentions; People/Accounts/Systems/Topics filter), Open tasks. Shared title/account/name filter and a Meetings/Other filter. Grouping is pure (`src/shared/library.ts`, tested). The last view is remembered.
40. **First-run setup guide** (5 steps: welcome, notes folder + your name, Google sign-in, optional AI key with per-provider instructions and a button that opens the key page, shortcuts). Skippable; shown once (`setupDone`); reopen from Settings or Ctrl+K. Key instructions live in `renderer/keyGuide.ts` and also appear on each provider card.
41. **Word cloud shows topics, not chatter.** Besides stop words it drops generic meeting filler, words in more than 60% of notes (boilerplate, once there are 8+ notes), and every part of a known person's name; folds simple plurals; ranks by distinctiveness (count x rarity) while showing real counts.
42. **Review fixes (2026-11-13).** CUI screening now also checks the text of every retrieved snippet and title (not only tags), and recognises spelled-out markings (Controlled Unclassified, FOUO, ITAR). The private Google session denies all permission requests (camera, microphone, location, notifications). A renderer error boundary replaces a blank window with a Reload screen. Package metadata corrected.
